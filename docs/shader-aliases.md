# Shader aliases (CryEngine / Far Cry)

The renderer resolves **logical shader names** (from materials, scripts, code) to **concrete effect names** using two data files loaded at init.

## Files

### `Shaders/Aliases.txt`

- **Format:** each non-comment line is two whitespace-separated tokens: `alias target`.
- **Semantics:** unconditional mapping. Every use of `alias` is rewritten to `target` before shader lookup.
- **Loaded into:** `CShader::m_AliasNames` (`SNameAlias`: `m_Alias` → `m_Name`).
- **Typical use:** shorthand names, renames without touching every asset (`Default` → `CGRCDefault`), shared bump templates (`TBumpSpec` → `TemplBumpSpec`).

### `Shaders/CustomAliases.txt`

- **Format:** conditional blocks with `{` … optional `}`; inside valid blocks, lines are `alias target` (optional `; comment`).
- **Conditions:**
  - **CVars:** e.g. `r_OffsetBump = 0` — aliases in that block apply only when the CVar matches.
  - **GPU:** `GPU = NV1X` | `NV2X` | `R300` | `NV4X` — compared to `gRenDev->GetFeatures() & RFT_HW_MASK`.
- **Semantics:** adds **extra** mappings only when the active condition matches.
- **Loaded into:** `CShader::m_CustomAliasNames`.
- **Post-processing:** the engine folds simple alias chains (if one row’s target equals another row’s alias, earlier rows jump to the final target).
- **Typical use:** different real shaders per GPU tier or quality CVar (e.g. GF2 paths vs PS2.0 paths, offset bump off → non-offset shader names).

## Resolution order

Implemented in `CShader::mfShaderNameForAlias` (`RenderDll/Common/Shaders/ShaderTemplate.cpp`):

1. Start from the requested string.
2. If the name is known to the global `CName` table (`CName(..., eFN_Find)` has an index), apply **`m_AliasNames`** first (Aliases.txt).
3. On the **result**, apply **`m_CustomAliasNames`** (CustomAliases.txt).

Shader loading (`mfForName` in `RenderDll/Common/Shaders/ShaderScript.cpp`) calls this **before** normalizing the path (`ConvertDOSToUnixName`, lowercasing) and looking up cached/loaded shaders.

Template selection (`mfShaderItemForName`) also runs `mfShaderNameForAlias` on **`tmplName`** when present so template names follow the same alias rules.

## Why this exists

- **Stable names in content:** levels and assets keep one name; the engine swaps implementation under GPU/settings.
- **Backward compatibility:** rename or consolidate shaders without mass asset edits.

## Metal port reality

The Dart toolchain ([`tools/shader_port/lib/alias_auditor.dart`](../tools/shader_port/lib/alias_auditor.dart), [`tools/shader_port/lib/metal_generator.dart`](../tools/shader_port/lib/metal_generator.dart)) folds **Aliases.txt** and **`CustomAliases.txt`** into manifest **`lookupAliases`** so legacy names resolve without duplicating C++ alias tables.

What the Metal port **does** support today:

- ✅ **Tier 1 — manifest fragments.** Primary lookup path. Generated by `metal_generator.dart` into `RenderDll/XRenderMetal/Generated/generated_manifest.json`.
- ✅ **Tier 2 — flat `Aliases.txt`.** Each row’s **target** is normalized (`ConvertDOSToUnixName` + lowercase). Targets that are CryEngine **template names** (not fragment IR names) are rewritten via **`kAliasesTxtTargetToManifestNormalized`** in [`tools/shader_port/lib/alias_auditor.dart`](tools/shader_port/lib/alias_auditor.dart) (`resolveAliasesTxtTarget`) to an existing manifest fragment `normalized` key. Aliases are then grouped onto that fragment’s `lookupAliases`. Any target that still does not match a manifest fragment after resolution is reported by `findUnmatchedAliasTargets` during generation (no silent drops).
- ✅ **Tier 3 — `CustomAliases.txt` (build-time merge).** The generator merges parsed conditional-block rows into the same **`lookupAliases`** map as Tier 2 (**first occurrence wins** globally; block conditions are not used to pick subsets). See **Tier 3 details** below.

**Template→manifest anchors (Aliases.txt targets)** — legacy `Aliases.txt` targets that never appear as ported shader basenames:

| Normalized target | Resolved manifest key |
|-------------------|------------------------|
| `nodraw` | `cgrcdefault` (anchors `no_draw`; does not reproduce invisible draws — shader semantics gap) |
| `templbumpdiffuse` | `cgrcbump_diff` |
| `templbumpdiffuse_nocm` | `cgrcbump_diff_singlelight_atten` |
| `templbumpspec` | `cgrcbump_diffspec_singlelight_ps20` |
| `templbumpspec_hp` | `cgrcbump_diffspec_singlelight_hp_atten` |
| `templbumpspec_nocm` | `cgrcbump_diffspec_singlelight` |
| `templbumpspec_glossalpha_envcmamb` | `cgrcbump_diffspec_singlelight_glossalpha_envcm_ps20` |

What the Metal port **does NOT** yet support:

- ❌ **Tier 4 — top-level `Shader 'X' ( … )` blocks.** Many "system shader" names the engine asks for are high-level CryEngine 1 shader objects defined in `.csl` files inside `Shaders.pak` (e.g. `CryLight`, `Terrain`, `TerrainWaterBeach`, `ParticleLight`, `FogLayer`, `ScreenTexMap`, `ScreenProcess`, `ShadowMapGen`, `BinocularDistortMask`, `ScreenDistort`). The Metal port has only the fragment-level `CGRC*` / `CGVProg*` programs — the high-level technique scripts that compose them are not interpreted.

**Tier 3 details (`CustomAliases.txt` on Metal)**

- **Codegen:** [`tools/shader_port/lib/metal_generator.dart`](../tools/shader_port/lib/metal_generator.dart) loads `Assets/Shaders/Source/Shaders/CustomAliases.txt` when present, runs **`parseCustomAliases`**, **`buildManifestLookupAliasesByTargetFromCustomAliasPairs`**, and **`mergeManifestLookupAliasMaps`** with the Tier 2 map. Architecture diagram: [`metal-shader-load-fatal-resolution.md`](metal-shader-load-fatal-resolution.md) — section **Build-time architecture — tiers 2–3**.
- **Target folding:** **`resolveCustomAliasesTargetForManifest`** in [`tools/shader_port/lib/alias_auditor.dart`](../tools/shader_port/lib/alias_auditor.dart) applies **`kIntermediateAliases`** (e.g. outdoor/indoor low-spec water FP → `cgrclowmedwater` / `cgrcindoorwater`) then **`resolveAliasesTxtTarget`**.
- **Gap vs PC:** **`CShader::mfShaderNameForAlias`** evaluates **CVar/GPU** gates per block; Metal codegen emits **one** merged alias table — no runtime conditional alias engine and no multi-profile manifests unless added later.

A separate set of names (`Default`, `OutSpace`, `FarTreeSprites`, `ClearStencil`, `<Stencil>`, `RainMap`, `SniperDistortMask`, `InfRedGal`) are **not defined anywhere** in the shipping game — they were resolved by hardcoded C++ fallbacks in the original `RenderDll`, which were intentionally removed in commit `d31e143`.

Consequence: when the engine calls `EF_LoadShader(name, …, EF_SYSTEM)` for a name that does not resolve to a manifest **`normalized`** key or a **`lookupAliases`** entry (after alias folding), or that exists only in **tier 4** (or nowhere), the Metal port hits `ShaderLoadFatal` and aborts. The strict policy, decision tree, caller-bug class, regression-test pattern, and resolution log live in [`metal-shader-load-fatal-resolution.md`](metal-shader-load-fatal-resolution.md).
